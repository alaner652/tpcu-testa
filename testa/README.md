# Testa frontend

Vue 3 (Composition API, `<script setup>`), TypeScript, Vite, Tailwind CSS v4, reka-ui, Lucide, KaTeX, vue-draggable-plus, vue-sonner.

```bash
npm install
npm run dev        # :5173, proxies /api to the backend on localhost:8080
npm test           # unit tests (vitest)
npm run build      # type check + production build
```

How to start the backend and the demo accounts: see the [root README](../README.md#quick-start).

## Pages

Hash routing, so URLs look like `http://localhost:5173/#/exams`. UI text is Traditional Chinese.

| Path | Who | Contents |
| --- | --- | --- |
| `/login` | everyone | Candidates: candidate number + login code. Staff: email + password |
| `/help` | everyone | Operation manual: a chapter per role, short clips with numbered steps; the candidate chapter prints |
| `/about` | everyone | About Testa for non-technical readers: how an exam runs (linking into the manual), why it is safe, credits |
| `/password` | staff | Change password (forced after signing in with a temporary one) |
| `/` | staff | Home: a to-do list, one button per item |
| `/banks` | authors, owners | Question banks |
| `/banks/:id` | authors | Bank editor (focus mode): edit / try it as a candidate |
| `/exams` | owners, proctors | Exams: create, publish, end |
| `/exams/:id` | owners, proctors | One exam: roster, login slips, proctoring, graders and results, emergency access |
| `/grading` | graders | Grading: one paper at a time, anonymous |
| `/members` | owners | Unit members and roles (from the account menu) |
| `/admin` | system administrators | Accounts, units, audit log, backups, emergency access |
| `/student` | candidates | My exams, results |
| `/student/exam/:id` | candidates | Taking the exam (focus mode): confirm identity, timed answering, submit |

The nav is a top tab bar on desktop and a bottom tab bar on phones. Route guards only redirect; the backend does the real permission checks.

## Conventions

- **Shared question cards**: a question looks the same in the editor as in the exam. Candidates and the teacher's "try it" mode share `ExamPreview` (switched by the `real` prop).
- **Confirm and feedback**: actions that are hard to undo (delete, submit, end exam, disable account...) go through `useConfirm()`; results are reported with a toast.
- **Demo features**: AI-assisted grading has no backend. It is wrapped in `DEMO_FEATURES` and hidden in production builds.
- **AI import** is real but optional: its buttons appear only when an administrator has turned it on (`useAi`).
- **System settings** (`SystemSettings.vue`) are for administrators who do not run servers: each field explains itself in plain words, and the AI address can be tested before saving.
- **Components**: `components/ui` follows the shadcn-vue style (reka-ui + cva + `cn()`), written by hand with this project's tokens, not generated by the CLI.

## Design tokens

Defined in `src/style.css`, one set each for light and dark.

| Token | Use |
| --- | --- |
| `desk` / `paper` / `sunken` | Canvas and cards (both white in light mode), inputs and hover |
| `ink` / `ink-2` / `ink-3` | Three levels of text |
| `brand` / `brand-strong` / `brand-soft` | Chalkboard green: brand, primary actions, correct answers |
| `grade` / `grade-soft` | Red: errors, warnings, delete only |
| `marker` / `marker-ink` | Yellow: pending (`bg-marker text-marker-ink`; there is no `marker-soft`) |

One sans-serif stack for the whole site; question content uses `.exam-text`, shared by the editor and the exam.

## UI principles

- One "next step" button per row; rarely used actions go into the "..." menu (`components/ui/MoreMenu.vue`).
- Buttons, tabs and nav items carry a Lucide icon.
- Whole cards are clickable; a one-line hint next to the status says what to do next.
- Keep explanatory text to what is needed.
- The same kind of UI uses the same component, so pages look alike: `NavCapsule` (the top bar of every full page, a dashed
  capsule), `BottomBar` (phone navigation, three cells and "更多"), `PageHeader` (page title, hint, actions),
  `CardHeader` (card title, count, one-line hint, actions), `TabBar` (tabs; the current one is a dashed capsule, `.pill-tab`),
  `EmptyNote` (empty or loading list), `ErrorNote` (failed load with a retry button), `FormError` (red line under a form),
  `SettingRow` with `ChoiceSelect` (a setting and its control). Write a new one only when nothing fits.
- Flat material: white page, cards outlined by a hairline, no floating shadows, no grey header bars in lists.
  A list is one card with rows split by lines; rows that need attention (a live exam) sort first;
  rows are white, and an exam ended more than 7 days ago turns grey.

### Picking several rows and keyboard shortcuts

Both only speed things up; every action still has a button.

- Lists where one action often applies to many rows (exam roster, admin accounts) use `useSelection`: long press, Ctrl or ⌘ click, or the row's check box (`SelectMark`, it replaces the avatar or seat number on hover) starts picking; Shift click picks a range.
  `SelectionBar` then floats at the bottom with the count and the batch actions. Batch actions call one backend endpoint that succeeds or fails as a whole.
- The question map has a "選取" button instead of long press, because holding a bubble drags it.
- Shortcuts are registered per page with `useShortcuts` and listed by `?` (`ShortcutHelp`, also in the account menu). Single keys never fire while typing or while an input method is composing.
  Keep them few and conventional: `/` search, `N` new, `Esc`, `Ctrl A`. The candidate exam page has none.

### Buttons (`components/ui/Button.vue`)

| Size | Where |
| --- | --- |
| `sm` | In list rows and card headers |
| `md` | Beside form fields (same height as `.field`) and page-level actions |
| `lg` | Full-width form submit (sign-in, setup, starting the exam) |

- Variants: `primary` (at most one per row or form), `outline` (secondary), `ghost` (cancel), `danger` (quiet red in a row, e.g. revoke), `destructive` (solid red, confirms deleting).
- In a pair the cancel button comes first and the confirming button last, as in the confirm dialog.
- Every button is pill-shaped by default; do not add `rounded-full` or height overrides.

### Status labels (`components/ui/Badge.vue`)

One size; the tone carries the meaning, the same everywhere:

| Tone | Meaning | Examples |
| --- | --- | --- |
| `live` | Happening now | 進行中, 作答中, 可以作答 |
| `done` | Finished or positive | 已交卷, 答對, 系統管理員 |
| `warn` | Waiting or worth a look | 已排程, 待閱卷, 離開畫面, 尚未換掉臨時密碼 |
| `danger` | A problem someone has to act on | 已鎖定, 差距較大, 答錯, 備份過期 |
| `neutral` | Inactive or plain information | 草稿, 已結束, 已停用, 已補時 |

Badges are for status only (a bank's subject is plain text).

### Row layout

Title or name, then its status badges on the same line; details on the second line; at the right edge, the one primary button, then "...", then `›` for clickable cards.
`MoreMenu` keeps its slot when a row has no extra actions, so buttons line up down a list.
